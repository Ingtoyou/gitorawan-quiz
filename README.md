## คำถามท้ายใบงาน

### 1. อธิบายความต่างระหว่าง `git switch -c ชื่อ` กับ `git switch ชื่อ`
- **`git switch ชื่อ`**: ใช้สำหรับสลับ (checkout) ไปยัง branch ที่มีอยู่แล้วในระบบ
- **`git switch -c ชื่อ`**: ใช้สำหรับสร้าง (create) branch ใหม่ขึ้นมา พร้อมทั้งสลับไปยัง branch นั้นทันที (`-c` ย่อมาจาก create)

### 2. ถ้าลืมกลับไป main ก่อนสร้าง branch ที่ 3 ผลลัพธ์บนกราฟจะเปลี่ยนไปอย่างไร
- กิ่งของ branch ที่ 3 (`feature/style`) จะแตกกิ่งต่อยอดมาจาก branch ที่ 2 (`feature/about`) แทนที่จะแยกออกมาจาก `main` ส่งผลให้ไฟล์ `about.html` และประวัติ commit ของสายก่อนหน้าติดมาด้วย และกราฟจะไม่เป็น 6 สายที่แยกออกจากจุดเริ่มต้นเดียวกัน (ถูกหักคะแนน 10 คะแนน)

### 3. เหตุใด commit ที่ผ่าน `--amend` จึงมีรหัสใหม่ ทั้งที่แก้เพียงข้อความ
- เพราะรหัส commit (SHA-1 Hash) ถูกคำนวณขึ้นจากข้อมูลทั้งหมดของ commit นั้น ๆ ได้แก่ ต้นไม้เนื้อหาไฟล์ (Tree), รหัส commit ก่อนหน้า (Parent), ข้อมูลผู้บันทึก (Author/Committer), วันเวลาที่บันทึก (Timestamp), และข้อความบันทึก (Commit Message) เมื่อมีการเปลี่ยนแปลงข้อความหรือเวลา ค่าแฮชที่ได้จากการคำนวณทางคณิตศาสตร์จึงเปลี่ยนไปเป็นรหัสใหม่เสมอ

### 4. ยกตัวอย่างสถานการณ์การทำงานเป็นทีมที่ conflict มีโอกาสเกิดสูงที่สุด พร้อมเสนอวิธีลดโอกาสนั้น
- **สถานการณ์**: สมาชิกในทีมต่างคนต่างแยกย้ายไปพัฒนาฟีเจอร์ใน branch ของตนเองเป็นเวลานานโดยไม่ดึง (pull) ความเปลี่ยนแปลงล่าสุดจากสายหลัก และมีการแก้ไขโค้ดในไฟล์เดียวกัน บรรทัดเดียวกัน หรือไฟล์ routing/config เดียวกัน เมื่อถึงเวลานำงานมารวม (merge) เข้าสู่ main พร้อมกันจะเกิด Conflict รุนแรง
- **วิธีลดโอกาสเกิด**:
  1. ซอยงานให้มีขนาดเล็กและอายุสั้น (Short-lived feature branches) แล้วรีบรวมกลับเข้า main สม่ำเสมอ
  2. อัปเดตสายงานตนเองให้ทันสมัยกับ main อยู่เสมอด้วยคำสั่ง `git pull --rebase origin main` หรือ merge main เข้ามาเป็นประจำ
  3. สื่อสารและแบ่งขอบเขตความรับผิดชอบในทีมให้ชัดเจน เพื่อหลีกเลี่ยงการเข้าไปแก้ไฟล์เดียวกันพร้อม ๆ กัน
